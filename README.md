# PropertyLens — .NET 8 + Angular 20 + Microsoft Access / Dapper sample

## Scope and source-document limitation

The supplied **Instructions.pdf** is the *Software Engineer Coding Assessment — Take-Home Addendum*, not the main candidate handout. It requests a full working project and short README but **does not specify the functional problem**. This sample therefore makes an explicit, reasonable assumption from `sample_listings.json`: build a real-estate listing explorer that detects potential duplicate properties across MLS feeds and highlights differences. **It must not be presented as verified compliance with the missing main handout.**

## Prerequisites

- **Windows x64**, .NET 8 SDK, Visual Studio 2022 (optional), Node.js 20.19+/22.12+ and npm.
- **Microsoft Access Database Engine x64** or x64 Microsoft Access with ACE OLE DB (`Microsoft.ACE.OLEDB.12.0`). App/runtime and provider architectures must match.
- Use **Windows PowerShell 5.1 x64** for COM-based creation of the genuine **Access 2007–2016 compatible `.accdb`** file. SQL Server and SQLite are not used.
- Access/ACE OLE DB is Windows-specific and is not recommended for high-concurrency production servers.

## Run locally (Windows)

1. Unzip the package; keep the three folders in their existing positions.
2. Open 64-bit Windows PowerShell in `Database` and run `./Initialize-Database.ps1`. This creates `Database/Listings.accdb` with 12 seeded rows. To overwrite it, run `./Initialize-Database.ps1 -Force` (destructive).
3. From `Backend`, run `dotnet restore Listings.sln`, `dotnet build Listings.sln`, `dotnet test Listings.sln`, then `dotnet run --project Listings.Api --launch-profile Listings.Api`. API at `http://localhost:5088`, Swagger at `http://localhost:5088/swagger`.
4. From `Frontend`, run `npm install` and `npm start`. Open `http://localhost:4200`.
5. If necessary, update `Backend/Listings.Api/appsettings.json` (`Access:DatabasePath`) and `Frontend/src/app/listing.service.ts` (API URL).

> **Database generation limitation**: This build environment is Linux without Microsoft ACE or the .NET SDK, so a genuine `.accdb` file cannot be created or tested here. The provided Windows initializer creates the file in the requested format. No fake/renamed database file is included.

## Backend organization and Swagger

`Program.cs` contains only DI, middleware, Swagger setup and `MapControllers()`. All REST endpoints use attribute-routed controller classes in `Backend/Listings.Api/Controllers/`: `ListingsController`, `PropertiesController`, `StatsController`, `HealthController`, and `DemoController`. Query filtering is handled separately in `Services/ListingFilters.cs`.

Swagger UI: **http://localhost:5088/swagger** (available when `ASPNETCORE_ENVIRONMENT=Development`). Swagger JSON: `http://localhost:5088/swagger/v1/swagger.json`. Swashbuckle is included in the API `.csproj`. API endpoints and Angular URLs are unchanged.

## API endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Verify the API is up |
| GET | `/api/listings` | All original feed rows; `city`, `status`, `minPrice`, `maxPrice`, `minBedrooms`, `search` |
| GET | `/api/listings/{id}` | One original MLS row |
| GET | `/api/properties` | Matched property groups, same filters plus `duplicatesOnly=true` |
| GET | `/api/stats` | Source / unique / matched / conflicting ZIP counts |
| POST | `/api/demo/reset` | Reload JSON rows, **development only**, overwrites database rows |

Dapper is used for the data read/row mapping. Writes use parameterized `OleDbCommand` with positional placeholders because ACE's `?` parameters are positional and must strictly follow the column order. Matching/filtering is an application service, allowing isolated unit tests and future modifications. The data is persisted **only in the Access database**, not a JSON-backed runtime store.

## Duplicate-matching behavior (demo heuristic)

Group records when (a) city/state match and rounded 4-decimal coordinates match, **or** (b) city/state and normalized street addresses match. Normalization standardizes `St/Street`, `Ave/Avenue`, `Rd/Road`, `Ln/Lane`, `Ct/Court`, `Blvd/Boulevard`, `Dr/Drive`, `Apt/Apartment/Unit`. ZIP differences do not block matches; they are surfaced as data quality flags. Prefer the most recent `listedDate` as the group's summary record, keeping every original listing unchanged. This is **potential-duplicate detection**, not definitive merging. No geographic-distance or fuzzy ML matching is claimed.

With the supplied 12 records, expected groups are **8 unique properties**, **4 multi-source matched pairs**, and **1 group with a ZIP conflict** (456 Oak Ave / Avenue). These expected numbers are derived from the provided input, not from a live Access execution.

## Developer notes / limitations

- Read-only exploration and matching are implemented; import reset is a developer-only operation and has no authentication, so do not expose it outside local development.
- The UI uses no external map keys or third-party listing API; it works with the supplied dataset.
- Revisit matching edge cases (units, false coordinate matches, inconsistent city names, geo tolerance) with the interviewer.
- Swagger and CORS are configured for localhost development. Swagger UI and the demo reset route are restricted to the Development environment. For deployment, add authentication, environment-specific config, validation/rate limiting, and review Access locking/concurrency limits.
- **Validation status:** Source files are generated and sample JSON was examined; compilation, tests, Windows ACE creation and browser execution have **not** been run in this Linux environment (no `dotnet`/ACE runtime).


### Price range validation
The Angular filters reject a minimum price greater than maximum price before sending any request, display a red inline error, and disable Apply filters until corrected. `GET /api/properties` also returns HTTP 400 for the same invalid range.

### Existing Access database filename
The default backend configuration uses `Database/RealEstateListings.accdb` (the Access file created manually). To use another location, edit `Access:DatabasePath` in `Backend/Listings.Api/appsettings.json`. The file is not bundled in the ZIP; use the locally created Access database.


### Optional filter query parameter fix

The Angular service now **omits** `null`, `undefined`, blank, and non-finite numeric filter values instead of serializing them into query strings. For example, setting a minimum price of 500 and leaving maximum price empty sends `GET /api/properties?minPrice=500`; it does not send `maxPrice=null`. All filters remain optional, and the backend rejects an actual minimum greater than the maximum with HTTP 400. The Angular form displays the validation error without sending that invalid request.

For Windows, ensure `Backend/Listings.Api/appsettings.json` points to your actual `.accdb` filename and location.


## Angular API URL configuration

- `Frontend/src/environments/environment.ts` is used by `npm start` / development and targets `http://localhost:5088/api`.
- `Frontend/src/environments/environment.production.ts` is used by `npm run build` and defaults to `/api` (same-origin deployment). If the production API is hosted separately, update `apiBaseUrl` to its full HTTPS URL.
- The Angular CLI swaps these files via `fileReplacements` in `Frontend/angular.json`. `listing.service.ts` imports `environment` and no longer hardcodes the API endpoint.
- Restart `ng serve` after editing `angular.json` or environment settings.
- Environment files are bundled into the browser and are **not secure storage**. Do not put passwords or API secrets in them.
